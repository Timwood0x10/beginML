# Calculus in Deep Learning: From Gradients to Backpropagation


Deep learning's core is **optimization** — adjusting parameters to minimize a loss function. Calculus provides:
- **Gradients**: directing parameter updates
- **The chain rule**: computing derivatives of composite functions
- **Backpropagation**: efficiently computing gradients through multi-layer networks


In deep learning, calculus is more than computing derivatives — it's the language of **Change** and **Sensitivity**. A neural network is essentially one giant composite function, and training is the process of using calculus (mainly the chain rule) to find the lowest point of energy (Loss) in parameter space. This chapter builds a complete picture from Taylor expansions and gradient flow to automatic differentiation (AD), connecting the math definitions all the way to PyTorch's `.backward()`.

---

## 1. The Physical Meaning of Derivatives and Gradients

In machine learning, the object we care about is the **Scalar Loss Function** $L: \mathbb{R}^n \to \mathbb{R}$.

### 1.1 Sensitivity Analysis
For a parameter $w$, the derivative $L'(w)$ isn't just a "slope" — it's a measure of **sensitivity**:
$$ \frac{dL}{dw} = \lim_{h \to 0} \frac{L(w+h) - L(w)}{h} $$
This means: if we apply a tiny perturbation $h$ to the weight $w$, the loss $L$ changes by $L'(w) \cdot h$.
*   If $\frac{dL}{dw} > 0$, then to decrease $L$, we need to decrease $w$.
*   If $\frac{dL}{dw} < 0$, then to decrease $L$, we need to increase $w$.

### 1.2 The Gradient
When the input extends to a vector $\mathbf{w} \in \mathbb{R}^n$, the derivative becomes the gradient $\nabla L$.
$$ \nabla_\mathbf{w} L = \left[ \frac{\partial L}{\partial w_1}, \frac{\partial L}{\partial w_2}, \dots, \frac{\partial L}{\partial w_n} \right]^T $$
**Geometric meaning**: the gradient vector $\nabla L$ points in the direction in which the function grows **fastest**.
**Engineering application**: Gradient Descent updates parameters along the opposite direction of the gradient — essentially **Steepest Descent**.
$$ \mathbf{w}_{t+1} \leftarrow \mathbf{w}_t - \eta \nabla L(\mathbf{w}_t) $$

## 2. Taylor Series and the Optimization Viewpoint

Why does gradient descent work? Why do we sometimes need second-order optimization (like Newton's method)? The answer lies in **local linearization** and **quadratic approximation**.

### 2.1 First-Order Taylor Expansion: Local Linearization
Near the point $\mathbf{w}_0$, the loss function can be approximated as a linear plane:
$$ L(\mathbf{w}) \approx L(\mathbf{w}_0) + \nabla L(\mathbf{w}_0)^T (\mathbf{w} - \mathbf{w}_0) $$
If we want $L(\mathbf{w}) < L(\mathbf{w}_0)$, take $\mathbf{w} - \mathbf{w}_0 = -\eta \nabla L(\mathbf{w}_0)$ (with $\eta$ very small), then:
$$ L(\mathbf{w}) \approx L(\mathbf{w}_0) - \eta \| \nabla L(\mathbf{w}_0) \|^2 $$
Since the squared norm is non-negative, this guarantees the Loss must decrease. This is the theoretical foundation of **SGD**.

### 2.2 Second-Order Taylor Expansion: Curvature and Newton's Method
To approximate the Loss Landscape more precisely, we need the second-order term:
$$ L(\mathbf{w}) \approx L(\mathbf{w}_0) + \nabla L(\mathbf{w}_0)^T (\mathbf{w} - \mathbf{w}_0) + \frac{1}{2} (\mathbf{w} - \mathbf{w}_0)^T \mathbf{H} (\mathbf{w} - \mathbf{w}_0) $$
where $\mathbf{H} \in \mathbb{R}^{n \times n}$ is the **Hessian Matrix**, containing the second-order partial derivatives $\frac{\partial^2 L}{\partial w_i \partial w_j}$ and describing the terrain's **Curvature**.

*   **SGD's limitation**: SGD only uses first-order information and treats the terrain as a flat plane. In long narrow valleys (high curvature), SGD oscillates.
*   **Newton's Method**: directly finds the extremum of the quadratic surface.
    $$ \mathbf{w}_{new} = \mathbf{w}_{old} - \mathbf{H}^{-1} \nabla L $$
*   **Engineering dilemma**: in deep learning, the parameter count $n$ can reach $10^9$. Computing $\mathbf{H}$ needs $O(n^2)$ space, and computing the inverse $\mathbf{H}^{-1}$ needs $O(n^3)$ time. This is infeasible in practice.
*   **Solution**: use **Momentum** or **Adam** (using the history of squared first-order gradients to approximate a diagonalized Hessian — i.e., adaptive learning rates).

## 3. The Chain Rule: The Soul of Backpropagation

Mathematically, a deep neural network is a composite function:
$$ L = f_L(f_{L-1}(\dots f_1(\mathbf{x}, \mathbf{w}_1) \dots), \mathbf{w}_L) $$
The core tool for computing gradients is the **chain rule**.

### 3.1 Scalar Form
Let $z = g(y), y = f(x)$, then:
$$ \frac{dz}{dx} = \frac{dz}{dy} \cdot \frac{dy}{dx} $$
This looks simple, but in a computational graph it means **gradients flow backward**.

### 3.2 Vector Form and the Jacobian
Let $\mathbf{y} = f(\mathbf{x})$, with $\mathbf{x} \in \mathbb{R}^n, \mathbf{y} \in \mathbb{R}^m$. The derivative is no longer a scalar but the **Jacobian matrix** $\mathbf{J} \in \mathbb{R}^{m \times n}$:
$$ J_{ij} = \frac{\partial y_i}{\partial x_j} $$
The chain rule generalizes to matrix multiplication:
$$ \frac{\partial \mathbf{z}}{\partial \mathbf{x}} = \frac{\partial \mathbf{z}}{\partial \mathbf{y}} \cdot \frac{\partial \mathbf{y}}{\partial \mathbf{x}} $$

### 3.3 Vanishing/Exploding Gradients
Consider a simple $L$-layer linear network $h_l = W_l h_{l-1}$ (ignoring activations):
$$ \frac{\partial Loss}{\partial W_1} = \frac{\partial Loss}{\partial h_L} \cdot \underbrace{\prod_{i=2}^{L} W_i}_{\text{chain product}} $$
*   If the eigenvalues of $W_i$ are $\lambda < 1$, the chain product drives gradients toward 0 (vanishing).
*   If the eigenvalues of $W_i$ are $\lambda > 1$, the chain product drives gradients toward $\infty$ (exploding).
**Solution**: ResNet's residual connection $h_{l+1} = h_l + F(h_l)$ introduces the additive term $\frac{\partial h_{l+1}}{\partial h_l} = I + \frac{\partial F}{\partial h_l}$, letting gradients flow losslessly through the $I$ channel (the gradient highway).

## 4. Automatic Differentiation (AD)

In engineering implementations (e.g., PyTorch/TensorFlow), we neither use symbolic differentiation (formula derivation is too complex) nor numerical differentiation (expensive and imprecise). We use automatic differentiation on a **Computational Graph**.

### 4.1 Computational Graphs and the Wengert List
Any complex neural network can be decomposed into a sequence of atomic operations (add, multiply, Sin, Exp).
*   **Forward pass**: compute in order and push intermediate results onto the stack.
*   **Backward pass**: starting from the Loss, apply the chain rule, multiply the gradient signal by the Local Jacobian, and propagate back in reverse order.

### 4.2 JVP and VJP
The heart of AD isn't computing the full Jacobian (too big) — it's computing **products**.
Backpropagation essentially computes the **VJP (Vector-Jacobian Product)**:
Let the scalar loss be $L$, the intermediate variable $\mathbf{y} \in \mathbb{R}^m$, and the input $\mathbf{x} \in \mathbb{R}^n$.
We already know $\mathbf{v} = \nabla_\mathbf{y} L$ (a vector).
We need $\nabla_\mathbf{x} L = \mathbf{v}^T \mathbf{J}_{y \to x}$.
PyTorch's `.backward()` keeps performing VJP operations without ever explicitly building $\mathbf{J}$.

## 5. Engineering Practice: Implementing MicroGrad from Scratch

To truly understand how calculus operates inside AI, we shouldn't just call `torch.autograd` — we should hand-write an automatic differentiation engine. Below is a minimal scalar autograd engine implementation (inspired by Karpathy's micrograd).

```python
import math

class Value:
    """
    A node that stores a scalar value and its gradient, supporting autodiff.
    """
    def __init__(self, data, _children=(), _op=''):
        self.data = data
        self.grad = 0.0  # stores dL/d(this), the derivative of the loss w.r.t. this node
        # backward function, defined by the operation that produced this node
        self._backward = lambda: None
        self._prev = set(_children)
        self._op = _op

    def __repr__(self):
        return f"Value(data={self.data}, grad={self.grad})"

    def __add__(self, other):
        other = other if isinstance(other, Value) else Value(other)
        out = Value(self.data + other.data, (self, other), '+')
        
        # define the local backward logic for addition
        # z = x + y => dz/dx = 1, dz/dy = 1
        # chain rule: dL/dx = dL/dz * dz/dx
        def _backward():
            self.grad += 1.0 * out.grad
            other.grad += 1.0 * out.grad
        out._backward = _backward
        return out

    def __mul__(self, other):
        other = other if isinstance(other, Value) else Value(other)
        out = Value(self.data * other.data, (self, other), '*')
        
        # define the local backward logic for multiplication
        # z = x * y => dz/dx = y, dz/dy = x
        def _backward():
            self.grad += other.data * out.grad
            other.grad += self.data * out.grad
        out._backward = _backward
        return out

    def tanh(self):
        x = self.data
        t = (math.exp(2*x) - 1)/(math.exp(2*x) + 1)
        out = Value(t, (self, ), 'tanh')
        
        # tanh' = 1 - tanh^2
        def _backward():
            self.grad += (1 - t**2) * out.grad
        out._backward = _backward
        return out

    def backward(self):
        """
        Run backpropagation after a topological sort
        """
        topo = []
        visited = set()
        def build_topo(v):
            if v not in visited:
                visited.add(v)
                for child in v._prev:
                    build_topo(child)
                topo.append(v)
        build_topo(self)
        
        self.grad = 1.0  # dL/dL = 1
        for node in reversed(topo):
            node._backward()

# === simulate neural network training ===

# 1. define inputs and weights
x1 = Value(2.0); x2 = Value(0.0)
w1 = Value(-3.0); w2 = Value(1.0)
b = Value(6.88137)

# 2. forward pass
# neuron: x1*w1 + x2*w2 + b
x1w1 = x1 * w1
x2w2 = x2 * w2
x1w1x2w2 = x1w1 + x2w2
n = x1w1x2w2 + b
o = n.tanh()  # activation output

# 3. backward pass
o.backward()

print("--- Result verification ---")
print(f"Output: {o.data:.4f}")
print(f"Gradient dw1 (dL/dw1): {w1.grad:.4f}")
print(f"Gradient dx1 (dL/dx1): {x1.grad:.4f}")

# mathematical verification:
# o = tanh(x1*w1 + x2*w2 + b)
# do/dw1 = (1 - o^2) * x1
# let's check:
expected_grad = (1 - o.data**2) * x1.data
print(f"Manually derived gradient: {expected_grad:.4f}")
```

Code analysis

This code reveals the core autograd mechanism of PyTorch:

* Dynamic graph construction: every operation (__add__, __mul__) creates a new Value node and records its parents (_children), thereby building the computational graph (DAG).

* Local derivatives and closures: each operation defines a _backward function inside itself, which captures the local derivative (e.g., the local derivative of multiplication is the other operand).

* Programmatic chain rule: the backward() function uses topological sorting, starting from the output node, calling each node's _backward in turn, passing out.grad to child nodes to accumulate gradients.
This is calculus at its most elegant in engineering.
