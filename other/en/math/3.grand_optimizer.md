## Gradient Optimization Algorithms in PyTorch

### 1. What Do Optimizers Actually Do? (The Common Foundation of All Optimizers)

- Goal: make the parameters $\theta$ move in the direction that reduces the loss $L(\theta)$
- The gradient $g = \nabla \theta L(\theta)$ tells us `which way to go`
- The most basic update: $\theta \leftarrow \theta - \eta \cdot g$
  - $\eta$ = learning rate (how big each step is)

Most optimizers = add a few "plugins" to this template:
- Momentum: remembers the `historical direction` (like inertia / rolling a snowball)
- Adaptive step size: each parameter has its own step size (easy-to-learn ones take small steps, hard ones take big steps)
- Bias correction: statistics are unreliable at the very start, so correct them first
- Weight Decay: equivalent to `L2 regularization`, prevents overfitting

---

### 2. What Optimizers Are in PyTorch? (Grouped by Idea)

A. Basic + Momentum family

1) SGD (Stochastic Gradient Descent)
- Update: $\theta \leftarrow \theta - \eta \cdot g$
- Intuition: just look at the current slope and go downhill
- When to use: small models, well-behaved data, or when you pair it with a good learning-rate schedule (common for training large vision models from scratch)

2) SGD + Momentum
- Formulas:
  - $v \leftarrow \mu \cdot v + g$
  - $\theta \leftarrow \theta - \eta \cdot v$
- Intuition: like rolling a snowball — if the direction stays consistent for a long time, it rolls faster and faster; it's hard to get stuck in small pits
- When to use: more stable and faster than plain SGD; a `classic, reliable baseline`

3) Nesterov (NAG, momentum with `foresight`)
- Formulas (intuitive form):
  - Look one step ahead: $ḡ = \nabla L(\theta - \eta \cdot \mu \cdot v)$
  - $v \leftarrow \mu \cdot v + ḡ$; $\theta \leftarrow \theta - \eta \cdot v$
- Intuition: probe one step in the direction of inertia before deciding how hard to push — turns more flexibly
- When to use: similar to Momentum, occasionally faster

B. Adaptive step size family (each parameter gets its own step size)

4) Adagrad
- Formulas:
  - $G \leftarrow G + g^2$ (element-wise accumulation)
  - $\theta \leftarrow \theta - \eta \cdot g / \sqrt(G + \epsilon)$
- Intuition: parameters whose gradients are always large → step size automatically shrinks; sparse features → can learn faster
- Drawback: G keeps growing, so the step size keeps shrinking
- When to use: sparse features (e.g., early NLP scenarios)

5) RMSprop
- Formulas:
  - $E[g^2] \leftarrow \rho \cdot E[g^2] + (1-\rho) \cdot g^2$ (moving average)
  - $\theta \leftarrow \theta - \eta \cdot g / \sqrt(E[g^2] + \epsilon)$
- Intuition: like an `adaptive shock absorber` — looks at the gradient strength over `a recent window`
- When to use: RNNs/non-stationary objectives; now mostly replaced by Adam

6) Adadelta
- Idea: on top of RMSprop, also adapt the learning rate away (use the history of updates to set the step size)
- Intuition: a small improvement that removes the need to tune the learning rate entirely
- When to use: small tasks where you don't want to hand-tune lr

C. The Adam family (momentum + adaptive combined; the most used)

7) Adam (one of the default first choices)
- Formulas (remember these three lines and you're good):
  - $m \leftarrow \beta_1 \cdot m + (1-\beta_1) \cdot g$ (average of gradients, like momentum)
  - $v \leftarrow \beta_2 \cdot v + (1-\beta_2) \cdot g^2$ (average of squared gradients, like RMSprop)
  - $\theta \leftarrow \theta - \eta \cdot \hat{m} / (\sqrt{\hat{v}} + \epsilon)$ (m̂, v̂ are bias-corrected)
- Intuition: the direction has memory (doesn't jitter), and the step size adapts (doesn't charge wildly)
- When to use: a good starting point for almost any deep learning task

8) AdamW (strongly recommended)
- Difference: `decouples` `weight decay` from Adam — regularization is more correct
- Intuition: a more reliable version of Adam; the default for modern large models (BERT/GPT/ViT)
- When to use: use it by default; NLP fine-tuning usually uses lr≈2e−5~5e−5; CV/MLP usually uses lr≈1e−3

9) RAdam (Rectified Adam)
- Idea: Adam's adaptation is statistically unstable early on, so `warm up` before letting it loose
- Intuition: don't sprint at the start; steady yourself first
- When to use: small batches or tasks that are unstable at the start of training

10) NAdam (Nesterov Adam)
- Idea: Adam + Nesterov momentum
- Intuition: Adam with a bit of `foresight`-style acceleration
- When to use: results close to Adam, occasionally faster

11) Adamax
- Idea: approximate v with the `infinity norm` (more stable against extreme gradients)
- When to use: rarely necessary; a small variant of Adam

12) SparseAdam
- Idea: only update the rows that `appeared` (for sparse gradients)
- When to use: huge embeddings/vocabularies

D. Others

13) RMSprop (already above) / Rprop (Resilient backprop)
- Rprop formula (core idea):
  - Look only at the gradient sign, not the magnitude; same sign → multiply step by 1.2, different sign → multiply by 0.5
  - $\theta \leftarrow \theta - sign(g) \cdot \Delta$ (Δ is each parameter's own step size)
- Intuition: doesn't suffer from gradient magnitude; each parameter learns its own step size
- When to use: small/shallow networks, non-deep tasks

14) ASGD (Averaged SGD)
- Idea: moving-average the parameters for smoother convergence
- When to use: convex problems/linear models; more traditional

15) LBFGS (quasi-Newton, second-order approximation)
- Intuition: doesn't just look at the slope — it also estimates `curvature`, reaching the answer in fewer steps
- Limitation: needs large batches or full gradients; high memory usage
- When to use: small models/small data where you want fast, high-precision convergence (e.g., style transfer, linear/shallow networks)

---

### 3. Selection Cheat Sheet (follow this if you don't want to think)

- Don't know what to use: AdamW (good enough 99% of the time)
- Training large-scale image classification from scratch: SGD + Momentum + LR schedule (cos/step) is often stronger
- Huge vocab/Embedding with sparse gradients: SparseAdam or Adagrad
- Small batch or unstable early training: RAdam (or AdamW + warmup)
- Small model/small data, want fast convergence: LBFGS
- RNN/legacy projects: RMSprop is worth a try

### 4. How to Use It in PyTorch (switching optimizers = changing one line)

```python
import torch.optim as optim

# commonly used
optim.Adam(model.parameters(), lr=1e-3)
optim.AdamW(model.parameters(), lr=1e-3, weight_decay=1e-2)
optim.SGD(model.parameters(), lr=0.1, momentum=0.9, nesterov=True)

# adaptive family
optim.Adagrad(model.parameters(), lr=1e-2)
optim.RMSprop(model.parameters(), lr=1e-3, alpha=0.99)
optim.Adadelta(model.parameters())  # usually no lr needed

# Adam family
optim.RAdam(model.parameters(), lr=1e-3)
optim.NAdam(model.parameters(), lr=1e-3)
optim.Adamax(model.parameters(), lr=2e-3)
optim.SparseAdam(model.parameters(), lr=1e-3)  # only for sparse parameters

# others
optim.Rprop(model.parameters(), lr=1e-2)
optim.ASGD(model.parameters(), lr=1e-2)
optim.LBFGS(model.parameters(), lr=1.0)  # needs a custom closure
```

5. Putting the `math` in plain words (intuition for the four core plugins)

- Momentum v: like inertia. Formula $v \leftarrow \mu v + g$; $\theta \leftarrow \theta - \eta v$
  - Benefit: accelerates on straightaways, more stable in turns, doesn't easily get trapped in small pits
- Adaptive denominator √(statistic): like automatic transmission. Big denominator → small step; small denominator → big step
  - Adagrad: uses the `historical sum of squares` as the denominator (gets slower and slower)
  - RMSprop/Adam: use a `recent moving average` as the denominator (more flexible)
- Bias correction $\hat{m}$, $\hat{v}$: with little data at the start, remove the `bias` first
- Weight decay: pull the weights a bit toward 0 each step (prevents overfitting)
  - AdamW handles it `separately`, so it doesn't affect the adaptive denominator (this is more correct than Adam)

### 6. Common Hyperparameter Cheat Sheet (don't overthink when starting)

- AdamW: lr=1e−3 (MLP/CNN), β=(0.9, 0.999), weight_decay=1e−2; NLP fine-tuning lr=2e−5~5e−5
- SGD+Momentum: lr=0.1 (with cosine/step decay), momentum=0.9, weight_decay=1e−4
- RMSprop: lr=1e−3, alpha=0.99
- Adagrad: lr=1e−2
- RAdam/NAdam: lr=1e−3

Small tips:
- Unstable training / huge gradients: gradient clipping (clip_grad_norm_)
- Big first, small later: use a learning-rate schedule (cosine/step/warmup)

### 7. Learning Rate Schedulers: Giving the Optimizer a Gearbox
The optimizer decides direction; the learning rate (LR) decides step size. Using the same LR the whole time is often not optimal:
- Early: far from the target, steps should be big (or warm up first).
- Late: close to the target, steps should be small, otherwise you'll bounce around the bottom forever.
PyTorch's torch.optim.lr_scheduler provides these shifting strategies:
1. StepLR / MultiStepLR (stair-step decay)
- Intuition: every fixed number of Epochs, knock the LR down. Like going down stairs.
  ```python
  # every 30 epochs, lr = lr * 0.1
  scheduler = optim.lr_scheduler.StepLR(optimizer, step_size=30, gamma=0.1)
  ```

- Scenario: classic CNN training (e.g., ResNet topping ImageNet).

2. CosineAnnealingLR / CosineAnnealingWarmRestarts (cosine annealing)
- Intuition: use a cosine function to temper the LR — big early, small late. Like the tides.
  ```python
  # cosine annealing
  scheduler = optim.lr_scheduler.CosineAnnealingLR(optimizer, T_max=10)
  ```
- Scenario: currently the most popular, general-purpose choice, especially when training from scratch.


3. ReduceLROnPlateau (monitor-based decay)
- Intuition: keep an eye on Loss or Accuracy. If there's no improvement for N consecutive rounds (patience), force a slowdown ("since you're stuck, try finer steps").
  ```python
  # when the monitored metric stops improving, lr = lr * 0.1
  scheduler = optim.lr_scheduler.ReduceLROnPlateau(optimizer, mode='min', patience=10, factor=0.1)

  # note: this scheduler needs an argument at step time
  # scheduler.step(val_loss)
  ```
- Scenario: when you don't know how to set the decay, let the model figure it out itself.

4. LinearLR / Warmup
- Intuition: at the very start of training, parameters are random and gradients can be extremely unstable. If the LR starts out huge, it can easily `lead the model astray`. So run a few steps with a tiny LR first (Warmup), and accelerate once the model is "warm".
- Implementation: usually paired with SequentialLR, or use HuggingFace's get_linear_schedule_with_warmup.

8. Advanced Optimization Tricks (prevent blowups, save memory, improve scores)

1. Gradient Clipping
- Problem: sometimes (especially RNNs or deep networks), gradients suddenly become enormous (gradient explosion), parameters fly out of the galaxy, and Loss turns into NaN.
- Countermeasure: no matter how big the gradient, force it to be `chopped` down to a fixed norm.
- Code (put it after backward(), before step()):
  ```python
  loss.backward()
  # clip the gradient norm to max_norm=1.0
  torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)
  optimizer.step()
  ```

2. Gradient Accumulation
- Problem: memory is too small, so Batch Size can only be 8 — but you want the effect of a 64 Batch Size?
- Countermeasure: run 8 forward/backward passes, accumulate the gradients, and update the parameters once you've collected 64 worth.
  ```python
  accumulation_steps = 8

  for i, (inputs, labels) in enumerate(dataloader):
      outputs = model(inputs)
      loss = criterion(outputs, labels)
      
      # note: divide loss by accumulation steps, because backward automatically accumulates gradients
      loss = loss / accumulation_steps 
      loss.backward()
      
      if (i + 1) % accumulation_steps == 0:
          optimizer.step()    # update parameters
          optimizer.zero_grad() # clear gradients
  ```

3. LBFGS's Special Usage (Closure)
- Background: LBFGS needs to evaluate the function multiple times to estimate curvature, so its usage differs from SGD/Adam.
```python
optimizer = optim.LBFGS(model.parameters(), lr=1)

def closure():
    optimizer.zero_grad()
    output = model(input)
    loss = criterion(output, target)
    loss.backward()
    return loss

# pass the closure function into step
optimizer.step(closure)
```

4. SWA (Stochastic Weight Averaging)
- Intuition: late in training, the model oscillates around the optimum. Where SGD stops may not be the true center. SWA averages the weights from multiple late time points, usually finding a flatter (better-generalizing) valley.
- Usage: torch.optim.swa_utils.
- Scenario: a competition score-boosting tool that improves generalization.

9. Common `Problem` Diagnosis and First Aid
Optimizers aren't magic. When Loss misbehaves, don't panic:

1. Loss is NaN (Not a Number)
  - Causes: gradient explosion, learning rate too big, division by zero (input data has 0 or NaN).
  - First aid: lower LR, add gradient clipping, check the input data, check whether the denominator has epsilon.

2. Loss doesn't drop (Stuck)
  - Causes: LR too small (like an ant moving house), bad initialization, a code bug (e.g., forgetting optimizer.zero_grad(), so gradients keep accumulating).
  - First aid: try raising LR 10x, check the code logic.

3. Loss oscillates wildly (Oscillation)
  - Causes: Batch Size too small, LR too big.
  - First aid: lower LR, increase Batch Size.

4. Training Loss drops but test Loss rises
  - Cause: overfitting.
  - First aid: increase weight_decay with AdamW, add Dropout, add data augmentation, early stopping.

10. Ultimate Summary (One-Liner)
- Default first pick: AdamW(lr=1e-3, weight_decay=1e-2)
- CV leaderboard chasing: SGD(momentum=0.9) + CosineAnnealingLR
- Not enough memory: use gradient accumulation.
- Training blew up: add gradient clipping.
- Fine-tuning large models: use an extremely small LR (1e-5 level).
