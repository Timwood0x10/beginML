# Important Curves in Machine Learning

There are several important curves in machine learning; they are key tools for model diagnosis and optimization. This article details the most core curves and their applications.

---

## 📈 1. Learning Curve

### 1.1 What Is a Learning Curve?

**Definition:**
A learning curve shows how the model's **performance** (usually accuracy or error) changes with **experience** (usually the number of training samples, or the number of training iterations).

In a standard learning curve plot, there are usually two lines:
1.  **Training Curve:** how the model performs on the data it has "seen."
2.  **Validation/Cross-Validation Curve:** how the model performs on data it has "not seen" (representing generalization).

* **X-axis:** usually the **amount of training data** (from small to large). Sometimes in deep learning, the X-axis is "Epochs" (number of training iterations).
* **Y-axis:** usually **error (Loss/Error)** (lower is better) or **score (Score/Accuracy)** (higher is better).

### 1.2 How Is a Learning Curve Generated?

#### Operationally: the iterative evaluation process
Suppose you have 1000 data points in total. The steps to generate a learning curve:

1.  **Take a small portion of data:** e.g., first use only 10 samples as the training set.
2.  **Train and evaluate:** train the model with these 10 samples.
    *   Compute its error on the training set (usually very low, because with few samples it's easy to memorize by rote).
    *   Compute its error on the validation set (usually very high, because too few samples mean it hasn't learned the pattern).
3.  **Increase the data amount:** next take 50, 100, 200... until you use all the training data.
4.  **Connect the dots:** at each data-size point, repeat step 2, record the error, and connect the points to form the learning curve.

#### Theoretically: the Bias-Variance Tradeoff
The shape of the learning curve is determined by "bias" and "variance" in statistics:

*   **When data is very small:** the model easily fits those few points perfectly (training error near 0), but knows nothing about unseen data (validation error extremely high). This is a sign of high variance.
*   **As data increases:**
    *   It's harder for the model to fit all points perfectly, so the **training error slowly rises**.
    *   The model learns more general patterns, so the **validation error gradually falls**.
*   **Final trend:** the two lines try to converge.

### 1.3 Diagnosing and Understanding the Learning Curve

Reading a learning curve mainly involves looking at the **positions** and **gaps** of the two lines. Using "Error" as the Y-axis (lower is better) as an example:

#### 🔴 Underfitting — High Bias
*   **Phenomenon:**
    *   **Training error** is high (stays high, won't come down).
    *   **Validation error** is also high, and roughly equal to the training error.
    *   The two lines converge in the end, but both at a high error level.
*   **Plain understanding:** the model is "too dumb" or "too simple." E.g., the data is a parabola but you insist on fitting it with a straight line. Give it more data and it still can't learn.
*   **Countermeasures:**
    *   ❌ Add more data (usually doesn't help).
    *   ✅ Use a more complex model (increase model complexity).
    *   ✅ Add more features (Feature Engineering).

#### 🔵 Overfitting — High Variance
*   **Phenomenon:**
    *   **Training error** is very low (near 0, excellent performance).
    *   **Validation error** is high (poor performance).
    *   **Key feature:** there's a **huge gap (Gap)** between the two lines, like a crocodile's open mouth.
*   **Plain understanding:** the model "memorizes by rote." It memorized all the answers to the practice questions, but can't handle the exam when the numbers change slightly.
*   **Countermeasures:**
    *   ✅ **Add more data** (this is the most effective method; as data increases, validation error usually falls and the gap shrinks).
    *   ✅ Reduce model complexity (Regularization).
    *   ✅ Reduce the number of features (Feature Selection).

#### 🟢 Ideal State (Good Fit)
*   **Phenomenon:**
    *   Training error is low.
    *   Validation error is also low.
    *   The two lines are close together and stabilizing.
*   **Understanding:** the model both learned the patterns and generalizes well.

### 1.4 Code Implementation

```python
import numpy as np
import matplotlib.pyplot as plt
from sklearn.model_selection import learning_curve
from sklearn.ensemble import RandomForestClassifier

# plot a learning curve example
def plot_learning_curve(estimator, X, y):
    train_sizes, train_scores, val_scores = learning_curve(
        estimator, X, y, 
        train_sizes=np.linspace(0.1, 1.0, 10),
        cv=5
    )
    
    plt.figure(figsize=(10, 6))
    plt.plot(train_sizes, np.mean(train_scores, axis=1), 
             label='Training score', marker='o')
    plt.plot(train_sizes, np.mean(val_scores, axis=1), 
             label='Validation score', marker='s')
    plt.xlabel('Number of training samples')
    plt.ylabel('Score')
    plt.legend()
    plt.title('Learning Curve')
    plt.grid(True)
```

### 1.5 Typical Pattern Diagnosis

| Pattern | Training error | Validation error | Diagnosis | Solution |
|------|---------|---------|------|----------|
| 🔴 High bias | High | High and close | Underfitting | Increase model complexity |
| 🔵 High variance | Low | High with big gap | Overfitting | Add data/regularization |
| 🟢 Ideal state | Low | Low and close | Good fit | Keep optimizing |



### 1.6 Special Case Deep Dive: The Theoretical Learning Curve of Linear Regression
![learning_curve](../images/learning_curves.png)

This is the most classic figure in machine learning theory. From the perspective of mathematical expectation, it precisely describes how $\mathbb{E}_{in}$ (training error) and $\mathbb{E}_{out}$ (test/generalization error) of a linear regression model change with the amount of training data $N$.

1. Core formulas:
    Assuming noise is $\sigma^2$ and the linear model's dimension is $d$, then

    $$
    \mathbb{E}_{in} = (1- \frac{d+1}{N} ) \sigma^2
    $$

    - The training error is always less than the true noise $\sigma^2$
    - Because the model uses $d+1$ degrees of freedom (parameters) to "memorize by rote" the noise in the training set, it performs better on the training set than the true situation (a false prosperity).
    - When $N$ is large, $\frac{d+1}{N}$ approaches 0, and the training error approaches $\sigma^2$.

    $$
    \mathbb{E}_{out} = (1 +\frac{d+1}{N}) \sigma^2
    $$

    - The validation error is always **greater** than the true noise $\sigma^2$
    - Because the noise the model fit on the training set becomes wrong predictions on the test set, increasing the error. And the larger $\frac{d+1}{N}$ (which is the cost of overfitting, also called the variance cost), the larger the validation error.

2. Key stages of the curve
 - Starting point $N \approx d+1$
    - Training error (green line) $\approx 0$: when the sample size $N$ exactly equals the parameter count $d+1$, the model can pass perfectly through all training points (the linear equation system has a unique solution). It looks invincible, but is in fact extremely overfit.
    - Test error (blue line) $\to \infty$: because the noise the model fit on the training set becomes wrong predictions on the test set, the error increases.

 - Endpoint/convergence process $N \to \infty$
    - As the data amount $N$ increases, the model can no longer memorize all points by rote, so $\mathbb E_{in}$ is forced to rise.
    - At the same time, the model learns the true pattern, so $\mathbb E_{out}$ starts to fall.
    - Final destination: both lines converge to the dashed line $\sigma^2$ (the noise level).

3. Phenomenon

Even with infinitely much data, the model's error cannot drop to 0 — only to the noise level $\sigma^2$. And all our efforts (adding data $N$) are meant to make the test error ($\mathbb E_{out}$) approach this theoretical limit as closely as possible.

## 📉 2. Loss Curve

### 2.1 Visualizing the Training Process

The loss curve records how the loss function's value changes during training; it's an important tool for monitoring training status.

```python
class LossRecorder:
    def __init__(self):
        self.train_losses = []
        self.val_losses = []
    
    def plot_loss(self):
        plt.figure(figsize=(10, 5))
        plt.plot(self.train_losses, label='Training loss')
        plt.plot(self.val_losses, label='Validation loss')
        plt.xlabel('Epoch')
        plt.ylabel('Loss')
        plt.legend()
        plt.title('Loss Curve')
        
        # key observation point
        if len(self.val_losses) > 10:
            min_val_idx = np.argmin(self.val_losses)
            plt.axvline(min_val_idx, color='r', 
                       linestyle='--', label='Best stopping point')
```

### 2.2 Mathematical Derivation

The gradient descent process of a loss function (such as MSE):

$$L(\theta) = \frac{1}{n}\sum_{i=1}^{n}(y_i - f(x_i; \theta))^2$$

Each iteration updates:
$$\theta_{t+1} = \theta_t - \eta \nabla L(\theta_t)$$

The curve records the $L(\theta_t)$ value at each epoch.

### 2.3 Typical Patterns of the Loss Curve

#### Training dynamics
- **Early stage**: large gradients → loss drops fast
- **Middle stage**: near optimum → loss drops slowly/oscillates
- **Late stage**: overtraining → validation loss starts rising (overfitting)

#### Anomaly diagnosis
1. **Loss doesn't drop**: learning rate too small or model problem
2. **Loss oscillates**: learning rate too large
3. **Validation loss rises**: overfitting, needs early stopping

## 🎯 3. ROC Curve

### 3.1 Core Concepts

The ROC curve (Receiver Operating Characteristic Curve) is an important tool for evaluating binary classification model performance.

```python
from sklearn.metrics import roc_curve, auc

def plot_roc_curve(y_true, y_pred_proba):
    fpr, tpr, thresholds = roc_curve(y_true, y_pred_proba)
    roc_auc = auc(fpr, tpr)
    
    plt.figure(figsize=(8, 6))
    plt.plot(fpr, tpr, label=f'ROC (AUC = {roc_auc:.2f})')
    plt.plot([0, 1], [0, 1], 'k--', label='Random guess')
    plt.xlabel('False Positive Rate (FPR)')
    plt.ylabel('True Positive Rate (TPR)')
    plt.title('ROC Curve')
    plt.legend()
```

### 3.2 Mathematical Derivation

- **TPR (sensitivity)**: $\text{TPR} = \frac{TP}{TP + FN}$
- **FPR**: $\text{FPR} = \frac{FP}{FP + TN}$

Changing the classification threshold $t$ gives different (FPR, TPR) points, which are connected into a curve.

### 3.3 Reading the ROC Curve

- **Diagonal line**: random classifier, AUC = 0.5
- **Top-left corner**: perfect classifier, AUC = 1.0
- **The closer the curve to the top-left corner**: the better the model performance

### 3.4 Why Do We Need the PR Curve?

![PR_curves](../images/PR2.png)
When positive and negative samples are extremely imbalanced (e.g., fraud detection, where positive samples are only 1.9%), the ROC curve fails. Because TN (true negatives) is too large, FPR is almost always 0, so the ROC curve always looks perfect (near the top-left corner), hiding the fact that the model can't catch the few positive samples.

#### PR curve definition
- X-axis (Recall): $Recall = \frac{TP}{TP + FN}$ (of all the bad guys, how many did you catch?)
- Y-axis (Precision): $Precision = \frac{TP}{TP + FP}$ (of the people you caught, how many are actually bad guys?)

#### Reading the PR curve
- **Ideal position**: top-right corner (Precision=1.0, Recall=1.0).
- **Trend**: usually the higher the Recall, the lower the Precision (to catch more bad guys, you inevitably catch some good guys by mistake).
- **Baseline**: no longer the diagonal; it's a horizontal line depending on the positive sample ratio (e.g., if positive samples are 1%, random guessing gives Precision 0.01).

Key information in the figure:
- Gray dashed line (Baseline): the gray dashed line in the figure is no longer 0.5 but lies flat at the bottom (about 1.9%).
    - This represents the accuracy of **random guessing**. If only 1.9% of samples are bad guys, closing your eyes and guessing everyone is a bad guy gives Precision of only 0.019. This intuitively shows the task's difficulty.
- Blue solid line (Precision-Recall):
    - The shaded area under the curve is AP (Average Precision); here AP=0.86, indicating excellent model performance.
    - The curve being **staircase-shaped (jagged)** is normal. Each additional false positive makes Precision drop vertically.
- Red point (Best F1):
    - The red point marked in the figure is the highest F1-Score point (Recall=0.79, Precision=0.93).
    - Engineering meaning: this is the best threshold choice. At this point, the model achieves the best balance between "catching all" and "catching accurately."


|Scenario|Preferred curve|Reason|
|---|---|---|
|Balanced samples (1:1)|ROC curve|Comprehensive evaluation of the model's overall discrimination ability|
|Extremely imbalanced (1:100)|PR curve|Focus on the prediction quality of the minority (positive) class|

## 📊 4. Validation Curve

### 4.1 Hyperparameter Tuning

The validation curve shows how model performance changes with a hyperparameter; it's an important tool for hyperparameter tuning.

```python
from sklearn.model_selection import validation_curve

param_range = np.logspace(-3, 2, 6)
train_scores, val_scores = validation_curve(
    RandomForestClassifier(), X, y,
    param_name="max_depth",
    param_range=range(1, 20),
    cv=5
)

plt.plot(param_range, np.mean(train_scores, axis=1), label='Training')
plt.plot(param_range, np.mean(val_scores, axis=1), label='Validation')
plt.xlabel('max_depth')
plt.ylabel('Score')
```

### 4.2 Applications of the Validation Curve

1. **Find the best hyperparameter**: the parameter value at the validation curve's peak
2. **Diagnose overfitting/underfitting**:
   - Large gap between training and validation curves → overfitting
   - Both curves are low → underfitting
3. **Parameter sensitivity analysis**: the steeper the curve, the more sensitive the parameter

## 🔑 5. Comprehensive Application of Curve Analysis

### 5.1 Joint Diagnosis with Multiple Curves

In real projects, you usually need to analyze multiple curves at once:

1. **Learning curve** → determine whether you need more data
2. **Loss curve** → monitor the training process, determine the early-stopping point
3. **ROC curve** → evaluate classification performance
4. **Validation curve** → choose the best hyperparameters

### 5.2 Practical Advice

✅ **Monitor multiple curves at once**  
✅ **Early stopping**: stop when validation loss stops decreasing  
✅ **Cross-validation**: get more stable curves  
✅ **Comparison experiments**: compare curves of different models

### 5.3 Common Pitfalls and Solutions

| Problem | Phenomenon | Solution |
|------|------|----------|
| Overfitting | Large gap in learning curve | Add data/regularization |
| Underfitting | Learning curve sits high | Increase model complexity |
| Unstable training | Loss curve oscillates | Adjust learning rate |
| Poor hyperparameter choice | Validation curve has no peak | Expand the search range |

## 6. Double Descent Curve
Note: this is a disruptive update to the traditional "learning curve" in the deep learning era.

![duble descent](../images/double2.png)

### 6.1 The Collapse of Traditional Beliefs
In classical statistics (as described in section 1.2 of this article), we believe:
Model too simple $\to$ underfitting (left side).
Model too complex $\to$ overfitting (right side of the U-shape bottom).
The generalization error curve is $U$-shaped

### 6.2 What Deep Learning Discovered
But in modern deep neural networks, researchers found that when the parameter count far exceeds the sample count (over-parameterization), the test error doesn't explode as expected — it falls again!


### 6.3 Curve Shape
Combined with the figure above, the double descent phenomenon can be divided into three key stages:

Left gray region: Under-parameterized
- Corresponds to the classic `bias-variance tradeoff`.
- The blue "Classic Sweet Spot" is the model complexity traditional theory considers optimal. Going further right, the test error (red line) starts rising into overfitting.

Middle dashed line: Interpolation Threshold
- Position:
$N \approx d$ (parameters $\approx$ samples).
`The gate of hell`: the test error (red line) spikes to its peak. At this point the model force-fits all the noise and is extremely unstable.
Right white region: Over-parameterized
- Training error (gray dashed line): note the gray dashed line at the bottom of the figure — after the threshold, it sticks firmly to 0. This means the model has completely "memorized" all the training data.
- Test error (red solid line): a miracle happens! Although the model is memorizing by rote, the test error keeps sliding down.

Conclusion: the red point on the far right (Modern Regime) is lower than the blue point on the left. This proves that a huge parameter count brings implicit regularization, achieving better generalization.

### 6.4 Implications
This figure breaks our fear of "overfitting." In the deep learning era, as long as the parameter count is large enough (far exceeding the sample count), "zero training error" is not only not a bad thing — it's the necessary path to better generalization.
