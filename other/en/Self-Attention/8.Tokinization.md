# Tokenization Algorithms Explained: The Bridge from Characters to Semantics

> **Abstract**:
> The Transformer doesn't understand human characters — it only understands numbers (IDs).
> Tokenization is the mathematical process of mapping natural language text $S$ to a sequence of integers $I$.
> This chapter deconstructs the derivation and code implementation of **BPE (Byte-Pair Encoding)** in depth, compares WordPiece and Unigram from an information-theory perspective, and finally uses `tiktoken` to reveal the root cause of why GPT "can't count words".

---

## 📐 1. The Mathematical Definition of Tokenization

A tokenizer is a function $T$ that maps a string $S$ to a sequence of token indices:

$$ T: S \to [t_1, t_2, \dots, t_n] \in \mathbb{V}^n $$

where $\mathbb{V}$ is the Vocabulary and $|\mathbb{V}|$ is the vocab size (LLaMA-2 is 32k, GPT-4 is 100k).

### Why Choose Subword?
We face two extremes:
1.  **Character-level**: $|\mathbb{V}| \approx 100$.
    *   *Drawback*: sequences get too long, Attention $O(L^2)$ cost explodes; single characters lack semantics.
2.  **Word-level**: $|\mathbb{V}| \approx 100,000+$.
    *   *Drawback*: the vocab is sparse and can't handle OOV (Out-Of-Vocabulary); "old" and "older" are treated as unrelated IDs.

**Subword** is the sweet spot, based on the assumption:
> **Any rare word can be decomposed into common subword units.**
> (e.g., "unfriendly" $\to$ "un" + "friend" + "ly")

## 🔄 2. BPE (Byte-Pair Encoding) — The Cornerstone of the GPT Family

BPE is currently the most mainstream tokenization algorithm (all of GPT, and LLaMA, use it).

### 1. Algorithm Logic (Frequency Maximization)
BPE is an **iterative merging** algorithm. Its mathematical goal: **maximize the compression rate of the text data**.

**Training process**:
1.  **Initialize**: initialize the vocab $\mathbb{V}$ with all characters (Bytes).
2.  **Count**: count the frequencies of adjacent character pairs $(A, B)$ in the corpus.
3.  **Merge**: find the most frequent pair, merge it into a new symbol $AB$, and add it to $\mathbb{V}$.
4.  **Loop**: repeat until $|\mathbb{V}|$ reaches the target.

### 2. Hand-Computed Derivation Example (Toy Example)
Corpus: `("hug", 10), ("pug", 5), ("pun", 12), ("bun", 4)`

1.  **Base Vocab**: `[b, g, h, n, p, u]`
2.  **Current segmentation**:
    *   `h u g` (10)
    *   `p u g` (5)
    *   `p u n` (12)
    *   `b u n` (4)
3.  **Count Pairs**:
    *   `u` + `g`: $10 + 5 = 15$
    *   `u` + `n`: $12 + 4 = \mathbf{16}$ (Max!)
4.  **Perform the merge**: `u, n` $\to$ `un`.
    *   The vocab gains `un`.
    *   The state updates to: `h u g`, `p un`, `b un`.
5.  **Next round**: count new combinations like `p`+`un`...

### 3. Byte-level BPE (BBPE)
An improvement introduced by GPT-2. Instead of handling Unicode characters, it processes **UTF-8 Bytes**.
*   **Advantage**: the Base Vocab is fixed at 256 (0x00-0xFF), so **`<UNK>` can never occur**. Any weird emoji or symbol can be encoded.

## 🔗 3. WordPiece and Unigram (Just Need to Know Them)

### 1. WordPiece (BERT)
*   **Difference**: BPE picks the pair with the highest **frequency**; WordPiece picks the one with the highest **mutual information (Score)**.
    $$ \text{Score}(x, y) = \frac{\text{freq}(xy)}{\text{freq}(x) \times \text{freq}(y)} $$
*   **Mathematical essence**: merge $x$ and $y$ only when they are **truly strongly correlated** (not merely because both are common). For example, `q` and `u` are strongly bound in English.

### 2. Unigram LM (LLaMA/T5)
*   **Difference**: BPE is bottom-up (Merge); Unigram is **top-down (Prune)**.
*   **Logic**:
    1.  Start with a super-large vocab.
    2.  Compute how much the total corpus **likelihood** would drop if a token were removed.
    3.  Remove the 10% of tokens whose removal costs the least, and iterate.
*   **Advantage**: supports **Subword Regularization** — the same word can have multiple segmentations during training, improving robustness.

## 🛠️ 4. Engineering Practice and "Gotchas"

### 1. Why Can't GPT Count the 'r's in "strawberry"?
This is a **dimensional collapse** caused by tokenization. The model doesn't see letters — it sees IDs.

**Python visualization (Tiktoken)**:
```python
import tiktoken

# Load GPT-4's tokenizer
enc = tiktoken.encoding_for_model("gpt-4")

text = "strawberry"
tokens = enc.encode(text)
token_bytes = [enc.decode_single_token_bytes(t) for t in tokens]

print(f"IDs: {tokens}")
print(f"Subwords: {token_bytes}")

# Output:
# IDs: [496, 675, 5666]
# Subwords: [b'str', b'aw', b'berry']
```

**Analysis**:
*   The model sees the three vectors `[496, 675, 5666]`.
*   Although the vector for `berry` (5666) implicitly carries semantics, the model **does not** directly see the 3 `r` characters.
*   **At inference time**: the model is like someone reading pictograms — it knows `berry` denotes a kind of berry, but unless it has specifically memorized how many letters that ID corresponds to, it's very hard to count them correctly.

### 2. The Vocab-Size Trade-off Formula
When designing a model, how do we decide whether $|\mathbb{V}|$ should be 30k or 100k?

$$ \text{Total Cost} \approx \underbrace{O(L^2)}_{\text{Attention computation}} + \underbrace{O(V \times d)}_{\text{Embedding parameters}} $$

*   **Large $V$ (GPT-4: 100k)**:
    *   High information density per token $\to$ shorter sequence length $L$ $\to$ faster inference.
    *   Drawback: huge Embedding layer, high memory usage, sparse words hard to train.
*   **Small $V$ (Llama: 32k)**:
    *   Lightweight Embedding layer.
    *   Drawback: $L$ gets longer, and Attention computation grows quadratically.

### 3. Glitch Tokens
If the training data isn't cleaned well, certain tokens (like the Reddit garbled user `SolidGoldMagikarp`) appear only a few times, so their Embeddings are undertrained. When the model encounters these IDs at inference time, its output degrades badly.

## 💻 5. Minimal BPE Code Implementation (From Scratch)

This code shows the soul of BPE: **count + merge**.

```python
def get_stats(ids):
    """Count the frequency of adjacent pairs"""
    counts = {}
    for pair in zip(ids, ids[1:]):
        counts[pair] = counts.get(pair, 0) + 1
    return counts

def merge(ids, pair, idx):
    """Replace a pair in the sequence with a new ID"""
    newids = []
    i = 0
    while i < len(ids):
        # match the pair without going out of bounds
        if i < len(ids) - 1 and ids[i] == pair[0] and ids[i+1] == pair[1]:
            newids.append(idx)
            i += 2
        else:
            newids.append(ids[i])
            i += 1
    return newids

# --- simulate the training process ---
# 1. initial corpus (Bytes)
vocab_size = 260 # assume we only expand 4 new words
ids = list(b"hug pug pun bun hug") 

# 2. iterative merging
num_merges = vocab_size - 256
for i in range(num_merges):
    stats = get_stats(ids)
    if not stats: break
    
    # find the most frequent pair
    best_pair = max(stats, key=stats.get)
    new_id = 256 + i
    
    print(f"Merge {i+1}: {best_pair} -> {new_id}")
    ids = merge(ids, best_pair, new_id)

print(f"Final IDs: {ids}")
```

## 🧭 Summary

| Feature | **BPE** (King) | **WordPiece** | **Unigram** |
| :--- | :--- | :--- | :--- |
| **Logic** | Highest frequency first | Highest correlation (mutual information) first | Smallest probability loss first |
| **Direction** | Merge (addition) | Merge (addition) | Prune (subtraction) |
| **Representative** | **GPT-4, LLaMA** | BERT | T5 |
| **One-liner** | Simple and brutal, high compression | Handles common collocations | Built-in regularization |
