# Chapter 12: Engram —— 条件存储：大模型稀疏化的“第二轴”

> **摘要**：
> 现有的稀疏模型（MoE）主要关注**条件计算（Conditional Computation）**。DeepSeek 提出的 **Engram** 引入了**条件存储（Conditional Memory）**。
> 它的核心逻辑：将 Transformer 从“通过计算模拟检索”的沉重负担中解放出来，通过 $O(1)$ 的哈希查表实现静态知识的原生读取。
> 本章将从数学建模、架构设计及系统工程三个维度，解析 Engram 如何在不增加计算量（FLOPs）的情况下，突破参数规模与长文本瓶颈。

## 一、 设计哲学：知识检索与组合推理的分离

DeepSeek 团队认为语言建模包含两项本质不同的任务：

1. **组合推理 (Compositional Reasoning)**：需深层动态计算（Transformer 的强项）。
2. **知识检索 (Knowledge Retrieval)**：处理静态、刻板的模式（如实体名、固定搭配）。

**Transformer 的局限性**：缺乏原生查表原语，迫使模型在早期层使用宝贵的 Attention 和 FFN 来“重建”静态知识，浪费了模型有效深度。

**Engram 的逻辑**：建立并行的“存储轴”，通过 $N$-gram 索引直接获取 Embedding，让主干网络专注于高阶推理。

## 二、 Engram 核心架构设计

Engram 的执行逻辑分为三个关键模块：**词表压缩**、**多头哈希检索**与**上下文感知融合**。

### 1. 词表压缩 (Tokenizer Compression)

为了处理 $N$-gram 的组合爆炸问题，Engram 执行了词表映射 $P: V \to V'$：

* **操作**：通过 NFKC 归一化、转小写、合并等效 Token（如 `Apple` 与 ` apple`）。
* **效果**：在 128k 词表上实现了 **23%** 的有效规模缩减，显著提升了 $N$-gram 存储的语义密度。

### 2. 多头哈希检索 (Multi-Head Hashing)

为实现海量参数（100B+）的 $O(1)$ 级寻址：

$$
z_{t,n,k} \triangleq \phi_{n,k}(g_{t,n}), \quad \mathbf{e}_{t,n,k} = \mathbf{E}_{n,k}[z_{t,n,k}]
$$

* **机制**：针对每个 $N$-gram 阶数（n=2, 3...），采用 $K$ 个独立哈希头。
* **逻辑**：利用 Multi-head 机制缓解哈希冲突。最终检索向量 $\mathbf{e}_t$ 是所有哈希头结果的拼接。

### 3. 上下文感知门控 (Context-aware Gating) —— 核心点

静态查表无法处理歧义（一词多义）。Engram 引入了动态门控机制：

* **Query**：当前层的隐藏状态 $\mathbf{h}_t$（聚合了全局上下文）。
* **Key/Value**：从 Engram 表中检索出的静态嵌入 $\mathbf{e}_t$。
* **门控系数 $\alpha_t$ 计算**：
  $$
  \alpha_t = \sigma \left( \frac{\text{RMSNorm}(\mathbf{h}_t)^\top \text{RMSNorm}(\mathbf{k}_t)}{\sqrt{d}} \right)
  $$
* **语义对齐**：若检索知识与上下文冲突，$\alpha_t \to 0$，自动过滤噪声。

## 三、 缩放定律与稀疏分配 (Sparsity Allocation)

论文提出了一个关键的工程问题：在总参数预算固定时，参数应如何分配给 MoE 专家和 Engram 存储？

### 1. U 型缩放定律 (U-shaped Scaling Law)

实验（Figure 3）证明：

* **纯 MoE ($\rho = 100\%$)**：模型缺乏专用存储，被迫用计算模拟记忆，效率次优。
* **纯 Engram ($\rho = 0\%$)**：模型丧失动态推理能力。
* **最佳实践**：将约 **20%~25%** 的稀疏参数分配给 Engram。

### 2. “有效深度”的增加

通过 LogitLens 分析，Engram 在早期层介入（如 Layer 2）表现最优。它分担了底层的静态建模任务，使得 Layer 5 的预测准确度就足以匹配基准模型 Layer 12 的水平。

## 四、 系统工程：突破 GPU HBM 的物理限制

Engram 的系统优势在于其 **确定性 (Deterministic)** 的存取模式。

### 1. 异步预取 (Runtime Prefetching)

* **MoE 的痛点**：路由依赖动态隐藏状态，必须算完前一层才知道去哪读专家，通信延迟难以掩盖。
* **Engram 的优势**：索引仅取决于 Token ID 序列。
* **实现**：系统在计算 Layer 0 时，即可预知后面所有 Engram 层的哈希 ID，从而通过 PCIe **异步预取** 存储在 **Host Memory (CPU RAM)** 中的嵌入。

### 2. 硬件感知效率 (Infrastructure-aware)

* **离载存储**：支持将 100B 级别的参数表 Offload 到 CPU 内存甚至 NVMe SSD。
* **性能损耗**：在 8B 模型上挂载 100B 参数，推理吞吐量损耗 **< 3%**，几乎完美掩盖了跨设备通信延迟。

## 六、空间博弈：Engram 模块的最优插入位置

论文通过大规模消融实验（Figure 5）揭示了 Engram 在 Transformer 纵向结构中的“层敏感度”。

### 1. 核心结论：早期介入优于深层注入

* **实验数据**：将单层 Engram 插入不同位置，**Layer 2** 表现出最佳的 Validation Loss（1.770），且随深度增加效果线性变差。
* **物理逻辑**：
  * **Layer 0-1 (太早)**：隐藏状态尚未经过 Attention 聚合，缺乏足够的全局上下文来生成精准的“门控信号 ($\alpha_t$)”，导致检索噪声高。
  * **Layer 2 (黄金位置)**：此时已经过一轮全局建模，足以生成高质量 Query，且能通过即时检索将主干网从“低级模式重建”中解放出来。
  * **Deep Layers (太晚)**：主干网已经通过算力浪费（Attention/FFN）辛苦完成了模式识别，此时再给 Engram，属于“锦上添花”而非“雪中送炭”，ROI 极低。

### 2. 进阶策略：多层交织 (Layered Insertion)

* **最佳实践**：论文建议将 1.6B 的记忆预算拆分，分别注入 **Layer 2** 和 **Layer 6**。
* **收益**：兼顾了“早期知识卸载”与“后期精细门控调制”，比单层大容量模块效果更稳健。

## 七、 记忆进化：Engram 如何更新与扩展？

这是一个最容易被误解的点：Engram 到底是一个“固化的权重”还是一个“可插拔的插件”？

### 1. 无需重训主干的“无限内存模式” (Infinite Memory Regime)

Engram 实现了 **参数量 (Parameters)** 与 **计算量 (FLOPs)** 的彻底解耦：

* **横向扩展**：你可以通过增加哈希桶的数量（$M$）来暴力扩充 Engram 表（如从 2.7B 扩至 100B+）。
* **实验验证**：论文证明在固定 MoE 主干（3B）不变的情况下，单纯增加 Engram 的 Slot 数量，验证集 Loss 遵循严格的**幂律（Power Law）**下降。
* **工程意义**：这意味着你可以通过增加存储而非算力，持续榨取模型性能。

### 2. 动态更新的三种路径

当知识库需要更新（例如出现了新的 $N$-gram 事实）时，Engram 提供以下方案：

* **路径 A：增量 Embedding 学习 (无需重训主干)**
  * 由于检索逻辑是确定性的（基于 $N$-gram 哈希），主干网络的 $W_{up}/W_{down}$ 矩阵一旦训好，其语义对齐空间已固定。
  * **操作**：只需针对新文档生成 $N$-gram，并仅更新/初始化对应的 Embedding Slot。这本质上是一种极低成本的 **参数高效微调 (PEFT)**。
* **路径 B：热插拔离载存储 (Offloading)**
  * Engram 支持将庞大的参数表（100B+）存在 CPU RAM 甚至 NVMe SSD 中。
  * **操作**：通过异步预取机制，可以在不中断推理的情况下，动态加载新的“记忆分片”。
* **路径 C：哈希冗余利用**
  * 利用“多头哈希”的冗余，通过轻量级微调 Router（门控层），让模型学会关注新写入的 Slot。

## 八、 关键技术误区澄清 (FAQ)

### Q: 既然是哈希检索，那如果出现哈希冲突（Collision）怎么办？

**A (务实解读)**：Engram 使用了 **Multi-head Hashing**。即使 Head 1 发生了冲突，Head 2 和 Head 3 生成不同 ID 的概率极大。最终向量由多个 Head 拼接，模型能够通过学习，在融合层自动过滤掉那些具有冲突噪声的维度。

### Q: Engram 检索到的 Embedding 会导致模型输出崩溃吗？

**A (严谨解读)**：不会。因为有 **Context-aware Gating**（公式 4）。如果检索出的 Engram 向量与当前上下文 $\mathbf{h}_t$ 的余弦相似度极低，门控 $\alpha_t$ 会趋近于 0，物理上阻断了这部分信号进入残差流。

## 总结：稀疏架构的进化方向

| 维度               | 传统 MoE (计算稀疏)      | **Engram (存储稀疏)**                    |
| :----------------- | :----------------------- | :--------------------------------------------- |
| **位置决策** | 遍布每一层               | **主要集中在早期层 (Layer 2/6)**         |
| **更新代价** | 极高 (需重训路由与专家)  | **极低 (可仅更新 Embedding Slot)**       |
| **硬件瓶颈** | 受限于 GPU 显存 (HBM)    | **突破显存，可利用 CPU 内存/SSD**        |
| **适用场景** | 处理逻辑、推理、动态变换 | **存储事实、实体、长尾知识、长文本锚点** |

1. **架构进化**：从单纯的“计算稀疏”转向“计算 + 存储”的双轴稀疏。
2. **存储层次化**：利用 Zipf 分布，频繁 $N$-gram 驻留 GPU HBM，长尾 $N$-gram 驻留 Host DRAM。
3. **计算解耦**：Engram 证明了我们可以通过“外挂内存”的方式，在不增加训练/推理 FLOPs 的前提下，继续通过 Scaling Law 扩展模型知识边界。

**一句话总结**：如果 MoE 是让大模型有了“多核大脑”，那么 Engram 就是让大模型拥有了一部可以即时检索且不占脑力的“百科全书”。
