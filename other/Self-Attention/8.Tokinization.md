# 分词算法详解：从字符到语义的桥梁

> **摘要**：
> Transformer 并不理解人类的字符，它只理解数字（ID）。
> Tokenization（分词）是将自然语言文本 $S$ 映射为整数序列 $I$ 的数学过程。
> 本章将核心解构 **BPE (Byte-Pair Encoding)** 的推导过程与代码实现，并从信息论视角对比 WordPiece 与 Unigram，最后通过 `tiktoken` 实战揭示 GPT "数不清单词" 的根本原因。

---

## 📐 一、分词的数学定义

分词器（Tokenizer）是一个函数 $T$，它将字符串 $S$ 映射为 token 索引序列：

$$ T: S \to [t_1, t_2, \dots, t_n] \in \mathbb{V}^n $$

其中 $\mathbb{V}$ 是词表（Vocabulary），$|\mathbb{V}|$ 是词表大小（LLaMA-2 为 32k，GPT-4 为 100k）。

### 为什么选择 Subword（子词）？
我们面临两个极端：
1.  **Character-level (字级)**：$|\mathbb{V}| \approx 100$。
    *   *缺点*：序列过长，Attention $O(L^2)$ 成本爆炸；单个字符缺乏语义。
2.  **Word-level (词级)**：$|\mathbb{V}| \approx 100,000+$。
    *   *缺点*：词表稀疏，无法处理 OOV (Out-Of-Vocabulary)；"old", "older" 被视为无关 ID。

**Subword (子词)** 是最佳平衡点，基于假设：
> **任何稀有的词，都可以被分解为常见的子词单元。**
> (e.g., "unfriendly" $\to$ "un" + "friend" + "ly")

## 🔄 二、BPE (Byte-Pair Encoding) —— GPT 系列的基石

BPE 是目前最主流的分词算法（GPT 全系列, LLaMA 均采用）。

### 1. 算法逻辑（频率最大化）
BPE 是一种**迭代合并**算法。它的数学目标是：**最大化文本数据的压缩率**。

**训练流程**：
1.  **初始化**：将词表 $\mathbb{V}$ 初始化为所有字符（Bytes）。
2.  **统计**：统计语料中相邻字符对 $(A, B)$ 的频次。
3.  **合并**：找到频次最高的对，合并为新符号 $AB$，加入 $\mathbb{V}$。
4.  **循环**：重复直到 $|\mathbb{V}|$ 达标。

### 2. 手算推导示例 (Toy Example)
语料库：`("hug", 10), ("pug", 5), ("pun", 12), ("bun", 4)`

1.  **Base Vocab**: `[b, g, h, n, p, u]`
2.  **当前切分**:
    *   `h u g` (10)
    *   `p u g` (5)
    *   `p u n` (12)
    *   `b u n` (4)
3.  **统计 Pair**:
    *   `u` + `g`: $10 + 5 = 15$
    *   `u` + `n`: $12 + 4 = \mathbf{16}$ (Max!)
4.  **执行合并**: `u, n` $\to$ `un`。
    *   词表新增 `un`。
    *   状态更新为：`h u g`, `p un`, `b un`。
5.  **下一轮**: 统计 `p`+`un` 等新组合...

### 3. Byte-level BPE (BBPE)
GPT-2 引入的改进。不处理 Unicode 字符，而是处理 **UTF-8 Bytes**。
*   **优势**：Base Vocab 固定为 256 (0x00-0xFF)，**永远不会出现 `<UNK>`**。任何奇怪的 Emoji 或符号都能被编码。

## 🔗 三、WordPiece 与 Unigram (了解即可)

### 1. WordPiece (BERT)
*   **区别**：BPE 选**频率**最高的；WordPiece 选**互信息 (Score)** 最高的。
    $$ \text{Score}(x, y) = \frac{\text{freq}(xy)}{\text{freq}(x) \times \text{freq}(y)} $$
*   **数学本质**：只有当 $x$和$y$ **真的强相关**（而非仅仅因为它们都很常见）时，才合并。例如 `q` 和 `u` 在英文中强绑定。

### 2. Unigram LM (LLaMA/T5)
*   **区别**：BPE 是自底向上 (Merge)；Unigram 是**自顶向下 (Prune)**。
*   **逻辑**：
    1.  先搞一个超级大的词表。
    2.  计算如果删掉某个 token，总语料的**似然概率 (Likelihood)** 会下降多少。
    3.  删掉损失最小的 10% token，循环迭代。
*   **优势**：支持 **Subword Regularization**，同一个词训练时可以有多种切分方式，增强鲁棒性。

## 🛠️ 四、工程实践与 "坑"

### 1. 为什么 GPT 数不清 "strawberry" 里的 'r'？
这是 Tokenization 导致的**维度坍缩**。模型看到的不是字母，是 ID。

**Python 可视化 (Tiktoken)**:
```python
import tiktoken

# 加载 GPT-4 的分词器
enc = tiktoken.encoding_for_model("gpt-4")

text = "strawberry"
tokens = enc.encode(text)
token_bytes = [enc.decode_single_token_bytes(t) for t in tokens]

print(f"IDs: {tokens}")
print(f"Subwords: {token_bytes}")

# 输出结果:
# IDs: [496, 675, 5666]
# Subwords: [b'str', b'aw', b'berry']
```

**分析**：
*   模型看到的是 `[496, 675, 5666]` 这三个向量。
*   虽然 `berry` (5666) 的向量里隐含了语义，但模型**并没有**直接看到 3 个 `r` 字符。
*   **推理时**：模型就像在看象形文字，它知道 `berry` 代表一种浆果，但除非它专门背过这个 ID 对应几个字母，否则很难数对。

### 2. 词表大小权衡公式
我们在设计模型时，如何决定 $|\mathbb{V}|$ 是 30k 还是 100k？

$$ \text{Total Cost} \approx \underbrace{O(L^2)}_{\text{Attention计算}} + \underbrace{O(V \times d)}_{\text{Embedding参数}} $$

*   **$V$ 大 (GPT-4: 100k)**:
    *   单 token 信息密度高 $\to$ 序列长度 $L$ 变短 $\to$ 推理快。
    *   缺点：Embedding 层巨大，显存占用高，稀疏词难训练。
*   **$V$ 小 (Llama: 32k)**:
    *   Embedding 层轻量。
    *   缺点：$L$ 变长，Attention 计算量平方级增长。

### 3. Glitch Tokens (故障 Token)
如果在训练数据中清洗不干净，某些 token（如 Reddit 乱码用户 `SolidGoldMagikarp`）只出现过几次，Embedding 没训好。推理时一旦遇到这些 ID，模型输出就会崩坏。

## 💻 五、极简 BPE 代码实现 (From Scratch)

这段代码展示了 BPE 的核心灵魂：**统计 + 合并**。

```python
def get_stats(ids):
    ```统计相邻 pair 的频率```
    counts = {}
    for pair in zip(ids, ids[1:]):
        counts[pair] = counts.get(pair, 0) + 1
    return counts

def merge(ids, pair, idx):
    ```将序列中的 pair 替换为新 ID```
    newids = []
    i = 0
    while i < len(ids):
        # 匹配到 pair 且不越界
        if i < len(ids) - 1 and ids[i] == pair[0] and ids[i+1] == pair[1]:
            newids.append(idx)
            i += 2
        else:
            newids.append(ids[i])
            i += 1
    return newids

# --- 模拟训练过程 ---
# 1. 初始语料 (Bytes)
vocab_size = 260 # 假设只扩充 4 个新词
ids = list(b"hug pug pun bun hug") 

# 2. 迭代合并
num_merges = vocab_size - 256
for i in range(num_merges):
    stats = get_stats(ids)
    if not stats: break
    
    # 找到频率最高的 pair
    best_pair = max(stats, key=stats.get)
    new_id = 256 + i
    
    print(f"Merge {i+1}: {best_pair} -> {new_id}")
    ids = merge(ids, best_pair, new_id)

print(f"Final IDs: {ids}")
```

## 🧭 总结

| 特性 | **BPE** (King) | **WordPiece** | **Unigram** |
| :--- | :--- | :--- | :--- |
| **逻辑** | 频率最高优先 | 关联度(互信息)最高优先 | 概率损失最小优先 |
| **方向** | Merge (加法) | Merge (加法) | Prune (减法) |
| **代表** | **GPT-4, LLaMA** | BERT | T5 |
| **一句话** | 简单暴力，压缩率高 | 解决常见搭配 | 自带正则化 |
