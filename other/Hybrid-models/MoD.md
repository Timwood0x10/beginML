# 深度稀疏化：Mixture of Depths (MoD) 与架构效率大对决

> **摘要**：
> 传统的 Transformer 对每个 Token 投入等量的计算资源，无论其是复杂的“逻辑词”还是简单的“标点符号”。
> **MoD (Mixture of Depths)** 通过动态预测 Token 的“重要性”，允许部分 Token 跳过计算层，实现了 FLOPs 的深度稀疏化。
> 本章将解构 MoD 的容量路由机制，并深度对比 **Jamba** 与 **MLA** 在解决计算瓶颈上的路径差异。

## 一、MoD 的数学本质：按需分配的“层预算”

MoD 的核心创新在于：它不是随机跳层，而是基于一个**固定容量（Capacity）**的路由机制。

### 1. 路由逻辑：从概率到排名

在每一层中，Router（Router通常是一个轻量MLP + sigmoid，训练时用辅助损失鼓励均匀分配。） 为每个 Token 计算一个标量得分 $s_i$。与 MoE 不同，MoD 设定了一个 **容量阈值 (Capacity $C$)**：只有得分排名前 $k$ 的 Token 才能进入计算分支，其余的走残差直连。

$$
\text{Output}_i = 
\begin{cases}
x_i + \text{Layer}(x_i) & \text{if } s_i \in \text{Top-k}(S, C) \\
x_i & \text{if } s_i \notin \text{Top-k}(S, C)
\end{cases}
$$

* **为什么要 Top-k 而非固定阈值？**
  * **工程对齐**：Top-k 保证了每一批次（Batch）进入计算层的 Token 数量是恒定的。这使得 GPU 的 Tensor 形状固定，避免了动态形状导致的计算开销。

### 2. 计算开销的缩减

若设定 $C = 0.5$（即每层只计算 50% 的 Token），在不改变总层数的情况下，推理阶段的 **FLOPs 直接减半**。

## 二、架构之争：Jamba vs. MLA vs. MoD

这三种技术代表了目前大模型优化的三个顶级维度。

### 1. 维度对比表

| 维度                    | **传统 MHA (Llama 3)** | **Jamba (Hybrid)**                    | **MLA (DeepSeek)**          | **MoD (Mistral)**            |
| :---------------------- | :--------------------------- | :------------------------------------------ | :-------------------------------- | :--------------------------------- |
| **核心思路**      | 暴力全算                     | **空间换效率**：用 SSM 替换 Attention | **数学换效率**：低秩压缩 KV | **稀疏计算**：动态跳过计算层 |
| **KV Cache 占用** | 100% (极高)                  | **~12.5%** (根源消灭)                 | **~6.7%** (极致压缩)        | 100% (但计算次数少)                |
| **推理速度**      | 慢 (受内存带宽限制)          | 极快 (线性复杂度)                           | 极快 (带宽需求低)                 | 较快 (算力需求低)                  |
| **能力损耗**      | 基准                         | 无损/略强                                   | 几乎无损                          | 轻微 (取决于压缩率)                |

### 2. 深度分析：Jamba vs. MLA

* **Jamba** 是一种**物理治疗**：它认为 Attention 本身太重了，所以干脆拆掉 7/8 的 Attention 层，换成轻量级的 Mamba。
* **MLA** 是一种**微创手术**：它保留了 Attention 的全量功能（保持了强大的联想能力），但在数学上把 KV Cache 压到了极点，让显存不再成为瓶颈。

## 三、常见误区与工程现实

### 1. 常见误区澄清

* **❌ MoD 会让模型变笨吗？**
  * **✅ 真相**：论文显示，通过增加模型总深度并配合 MoD（例如 64 层 MoD 模型，计算量等同于 32 层 Dense 模型），其性能往往**优于**同等计算量的 Dense 模型。因为模型学会了将“脑力”花在刀刃上。
* **❌ 为什么 MoD 没被大规模应用？**
  * **✅ 工程挑战**：**KV Cache 存取的一致性**。如果一个 Token 在第 5 层被跳过了，那么后续层在引用该 Token 的 KV 时，需要特殊处理其“缺失”的状态。

### 2. MoD 的最佳拍档：MoE

当 MoD 遇到 MoE，就诞生了 **Mixture-of-Experts-and-Depths**：

1. **MoD** 决定：这个 Token 是否值得这一层的计算？
2. **MoE** 决定：如果值得，应该分给哪个专家？

这种**纵向（深度）+ 横向（专家）**的双重稀疏化，被认为是通往“万亿参数、千元推理”的终极路径。

---

## 四、工程实测：深度不是越多越好

在 Mistral 的实验中，采用 **“够用就好”** 策略：

* **事实性词汇**（如：名字、日期）：Router 分数极高，经过所有层。
* **结构性词汇**（如：of, the, 逗号）：Router 分数极低，跳过 60% 的计算。

**结论**：MoD 证明了 LLM 的推理存在显著的**计算冗余**。

## 🧭 总结：进入“按需计算”时代

| 特性               | **MoD**                | **MoE**            | **MLA**            |
| :----------------- | :--------------------------- | :----------------------- | :----------------------- |
| **优化方向** | 纵向（跳层）                 | 横向（分流）             | 显存（压缩）             |
| **一句话**   | 重要的词多算，不重要的词少算 | 专业的事交给专业的专家做 | 用最少的内存存最久的历史 |

> **结语**：
> 如果说 MLA 解决了“记不住”的问题，MoE 解决了“懂得多”的问题，那么 MoD 则解决了“算太累”的问题。三者的融合将是未来 Agentic LLM（智能体大模型）的底层基石。
